# Документация RSK Odessa

Готовые к печати инструкции для сотрудников: как установить приложение, как им пользоваться
и что делает каждая должность. В папке лежат и **PDF** (их и отправляют людям), и **HTML-исходники**
(из них PDF собираются одной командой).

## Что внутри

| Файл | Кому | О чём |
| --- | --- | --- |
| `Инструкция-01-Установка-приложения.pdf` | всем сотрудникам | Установка как приложения (PWA) на Android, iPhone/iPad, Windows, macOS; обновление версии; работа без интернета; если не устанавливается; удаление и переустановка |
| `Инструкция-02-Начало-работы.pdf` | всем сотрудникам | Вход и регистрация, шапка и разделы, кабинет (баланс, авансовый отчёт, мои заявки и задачи), статусы, общие правила, кто что видит, частые вопросы |
| `Инструкция-03-Администратор.pdf` | Администратор | Выдача доступов, карточки сотрудников (блокировка, восстановление, привязка аккаунта), касса и финансовые заявки, объекты и смета, права на двух уровнях (UI + RLS), чек-листы |
| `Инструкция-04-Директор.pdf` | Директор | Цифры и план-факт по всем объектам, контроль заявок и долгов, согласование и выдача денег, реестр и выгрузки, постановка задач |
| `Инструкция-05-Главный-инженер.pdf` | Главный инженер | Смета, график работ, документация, план-факт и доп. расходы, заявки на материалы, касса, задачи, реестр |
| `Инструкция-06-Прораб.pdf` | Прораб | Свои объекты: задачи с фотоотчётом, заявки на материалы и деньги, подотчёт и авансовый отчёт, закрытие разделов графика |

прочитать с телефона или отправить ссылкой.

## Пересобрать PDF

PDF собираются headless-браузером из HTML: `@page { size: A4 portrait }` и правила
`@media print` лежат в `docs.css`, поэтому дополнительно ничего настраивать не нужно.

```powershell
# из корня репозитория
powershell -ExecutionPolicy Bypass -File tools/make-docs.ps1
```

Скрипт берёт все `*.html` в этой папке, печатает каждый в одноимённый `.pdf` и пишет в консоль
размер результата. Нужен установленный Chrome или Edge.

Вручную то же самое:

```powershell
& "$env:ProgramFiles\Google\Chrome\Application\chrome.exe" --headless=new `
    --no-pdf-header-footer --virtual-time-budget=6000 `
    "--print-to-pdf=$PWD\Документация\Инструкция-06-Прораб.pdf" `
    "file:///$($PWD.Path -replace '\\','/')/Документация/Инструкция-06-Прораб.html"
```

## Правила оформления

* `docs.css` — общий стиль всех документов, включая печатный. Новые документы подключают его
  строкой `<link rel="stylesheet" href="docs.css">` и вставлять свои стили не должны.
* Логотип берётся из корня репозитория (`../logo.png`), поэтому папку можно переносить целиком
  и открывать даже по `file://`.
* Структура документа: `header.cover` (логотип, надзаголовок, название, лид, «чипы»),
  далее `section.sec` с `h2` (нумерованный раздел) — так PDF собирается в аккуратные страницы.
* Готовые блоки: `.cards` / `.card`, `.steps` (нумерованные шаги), `.note` / `.warn` / `.ok` /
  `.danger` (врезки), `.pills` (статусы), `.check` / `.cross` (чек-листы), `table` (таблицы).

## Важно: это внутренние документы

Инструкции описывают роли, права и порядок работы с деньгами — в интернет их выкладывать нельзя.
Вместе с `Презентация.html` / `Презентация.pdf` они перечислены в `.vercelignore` в корне репозитория,
поэтому при деплое приложения на Vercel эти файлы не попадают на публичный хостинг.
PDF передавайте сотрудникам напрямую (почта, мессенджер, папка на диске).

При изменении прав ролей (`js/permissions.js`) инструкции нужно обновить: матрица доступа описана
в «Инструкция-02-Начало-работы» и в файлах по должностям.
