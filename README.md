# RSK Odessa — управление строительством

Одностраничное веб-приложение (SPA) для учёта строительных объектов: сметы и график работ,
заявки на материалы и финансы, подотчёт, задачи, реестр расходов и дашборды.

**Стек:** HTML + Tailwind (CDN) + vanilla JavaScript (ES-модули), бэкенд — Supabase
(Postgres + Auth + Storage) через Cloudflare Worker-прокси. Сборки нет: файлы отдаются как есть.

## Запуск

Сборка не нужна, но `file://` не подойдёт — ES-модули работают только по HTTP.
Поднимите любой статический сервер из корня репозитория:

```bash
# вариант 1
python -m http.server 8080

# вариант 2
npx serve .
```

Затем откройте `http://localhost:8080/`.

Настройки подключения — в `js/config.js` (`CONFIG.SUPABASE_URL`, `CONFIG.SUPABASE_ANON_KEY`,
`CONFIG.STORAGE`, `CONFIG.POSITIONS`, `CONFIG.UNITS`). Anon-ключ Supabase публичный по дизайну —
данные защищаются политиками RLS на стороне БД, а не секретностью ключа.

## Структура

```
index.html            разметка всех экранов и модальных окон
css/style.css         кастомные стили (в т.ч. стили Gantt)
js/main.js            точка входа: навигация, права к UI, формы, boot
js/config.js          конфигурация + подключение к Supabase
js/database.js        единственный слой доступа к БД (select/insert/update/remove/...)
js/utils.js           форматирование, тосты, модальные окна, логи, roundMoney
js/permissions.js     матрица прав по ролям (ROLE_PERMISSIONS, TAB_REQUIREMENTS)
js/auth.js            вход/выход, привязка сотрудника к аккаунту
js/modules/*.js       разделы: employees, projects, estimate, gantt, orders, cash,
                      cash-requests, registry, tasks, files, dashboard
database/schema.sql   реконструкция схемы БД по коду (см. предупреждение в файле)
```

Правило проекта: модули **не обращаются к Supabase напрямую** — только через `js/database.js`.

## Роли и права

Единственный источник правды — `js/permissions.js`:

* `ROLE_PERMISSIONS` — что может роль (Администратор, Директор, Главный инженер, Снабженец,
  Инженер ПТО, Прораб);
* `TAB_REQUIREMENTS` — какая вкладка каким правом закрыта;
* `can(action)` / `canSeeTab(tab)` / `requirePermission(action)` — проверки в коде.

UI скрывает недоступные кнопки, но это только удобство: настоящая защита — политики RLS в Postgres.
Список должностей для форм — `CONFIG.POSITIONS`, он должен совпадать с ключами `ROLE_PERMISSIONS`,
иначе роль получит доступ «по минимуму» (в консоль пишется предупреждение).

## Важные инварианты

* **Номера заявок** (`З-…` для материалов, `Ф-…` для финансов) считаются как «максимум за год + 1»
  (`db.getNextRequestNumber()` и `generateCashRequestNumber()`), а не через `COUNT(*)`, и при коллизии
  (ошибка Postgres `23505`) запрос повторяется. `COUNT` ломается при удалении заявок и в параллельных сессиях.
* **Повторная загрузка сметы** не пересоздаёт разделы: строки сопоставляются по нормализованному имени,
  обновляются только план-суммы, а `planned_start_date` / `planned_end_date` / `actual_end_date`,
  проставленные в графике, сохраняются. Удаляются лишь разделы, которых больше нет в файле.
* **Блок сметы (`#estimate-block` → `renderEstimateUI()`) живёт только на подвкладке «📁 Файлы»** карточки
  объекта, рядом с «📁 Документация по объекту». На подвкладке «📊 План-факт» его держать нельзя: её
  содержимое целиком перезаписывает `renderSectionsUI()` через `innerHTML`, и любой статичный контент там
  (включая кнопку загрузки сметы) стирается сразу после открытия карточки. `switchProjectSubTab('files')`
  перерисовывает блок при каждом входе на подвкладку.
* **Подвкладка карточки объекта** — второй аргумент: `openProjectDetail(id, 'files')`. Так после
  загрузки/удаления сметы пользователь остаётся на «📁 Файлы», а не выбрасывается на «Общая информация».
* **На кнопках навигации счётчиков нет**: `#tasks-badge`, `#projects-badge`, `#employees-badge`,
  `#orders-badge`, `#cash-requests-badge` и функции `updateTasksBadge()` / `updateProjectsBadge()` /
  `updateEmployeesBadge()` / `updateOrdersBadge()` удалены, из подписей убраны «(N)». Причина: разделы
  грузятся лениво, поэтому до первого открытия вкладки счётчики показывали `0` и вводили в
  заблуждение. `updateCashRequestsNavButton()` (`js/modules/cash-requests.js`) по-прежнему показывает
  или скрывает кнопку «💰 Заявки финансов» по правам, но цифру не выводит.
* **Удаление объекта** идёт каскадом вручную (`confirmDeleteProject`): сначала файлы в Storage,
  затем позиции заявок, потом заявки/задачи/расходы/разделы и только после этого сам объект.
  Не полагайтесь только на `ON DELETE CASCADE` — его может не быть в БД.
* **Загрузка данных ленивая**: на старте грузятся только задачи (нужны для личного дашборда
  сотрудника), остальные разделы подтягивает `switchTab()` при первом открытии вкладки.
* **Фильтрация — на стороне БД** (`id.in`, `section_id.in`, `status.in`, `operation_type`), а не выкачиванием
  всей таблицы в браузер.
* Деньги считаются через `roundMoney()` из `js/utils.js` — не «сырой» арифметикой с плавающей точкой.

## Ограничения и что стоит доделать

* **Tailwind подключён как Play CDN** (`cdn.tailwindcss.com/3.4.17`) — версия запинена, но SRI для него
  поставить нельзя: CDN не отдаёт `Access-Control-Allow-Origin`. Для продакшена правильнее собрать
  CSS заранее и отдавать локальный файл. Остальные CDN-скрипты (xlsx, supabase-js, frappe-gantt,
  html2canvas, jsPDF) уже подключены с `integrity` + `crossorigin`.
* **RLS в Supabase из фронтенда не проверяется.** Перед выдачей доступа убедитесь, что политики закрывают
  чтение/запись по ролям: фронтенд-проверки `can()` защитой не являются.
* **`database/schema.sql`** — реконструкция по коду (таблицы, колонки, внешние ключи), а не дамп боевой БД.
  Индексы, триггеры, RLS и настройки Storage здесь отсутствуют — сверяйтесь с реальной базой.
* Приложение не кэширует данные для офлайна: при потере сети показывается предупреждающая полоса,
  сохранение в этот момент не сработает.

## Проверка кода

Тестов и сборки нет. Минимальная проверка синтаксиса после правок:

```bash
node --check js/main.js
```

(для файлов с `import`/`export` Node требует расширение `.mjs` либо флаг `--input-type=module` —
удобно проверять копией файла с расширением `.mjs`).
